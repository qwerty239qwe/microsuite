# 0.4.0 — MaAsLin 3 Backend Plan

- **Date:** 2026-08-05
- **Status:** Planned; moved from the 0.3.0 design
- **Source:** `docs/superpowers/specs/2026-08-02-diffab-unification-and-batch-correction-design.md`

## Objective

Add MaAsLin 3 as a new differential-abundance backend on the unified formula
surface. MaAsLin 2 remains available and is not upgraded in place: reproducible
published analyses need to retain the version they used.

## Deliverables

1. Add `src/microsuite/diffab/r/maaslin3.R` using the shared `params.json`
   convention.
2. Add a `containers/r-diffab-maaslin3` image following the existing per-backend
   R image pattern, with a build-time smoke test.
3. Register `maaslin3` in the Python API, CLI dispatch, capabilities, and method
   documentation.
4. Pass through fixed and random formulas, plus configurable `normalization`,
   `transform`, `min_prevalence`, and `min_abundance` settings. Defaults must
   preserve the 0.2.1 TSS normalization correction.
5. Define an output contract for MaAsLin 3's separate abundance and prevalence
   result tables. They must remain distinguishable rather than being flattened
   into one ambiguous table.

## Why this is a separate 0.4.0 work package

MaAsLin 3 adds subject-level random effects, distinct abundance/prevalence
testing, group-wise differences, and ordered predictors. The two-table result
contract and dedicated container require more integration and validation than
the 0.3.0 formula-surface work should carry.

## Validation

- Unit-test option forwarding and rejection with mocked subprocess calls.
- Add an opt-in integration smoke test gated by the R package and an environment
  variable.
- Use deterministic synthetic data with a planted association.
- Assert that the association is recovered and that abundance and prevalence
  outputs are both present and distinct.
- Verify the Docker image independently in CI.

## Documentation

- Document MaAsLin 3 alongside MaAsLin 2, emphasizing that it is an addition,
  not a replacement.
- Document the separate abundance/prevalence outputs and all configurable
  normalization and filtering parameters.
- Add the release note to `CHANGELOG.md` under 0.4.0.

This work can share the broader 0.4.0 diversity ergonomics and provenance
follow-ups already recorded in the 0.3.0 design, but it is independently
testable as a backend work package.
