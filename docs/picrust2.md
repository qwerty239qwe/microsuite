# PICRUSt2 functional profiling

microsuite 0.6.0 supports PICRUSt2 v2.6.3 through the dedicated
`microsuite-picrust2` image. The image contains the upstream PICRUSt2-SC
reference files and the legacy PICRUSt2-oldIMG files/scripts. The default
selector is `SC`, matching PICRUSt2 v2.6.0 and later.

PICRUSt2 predicts functional potential from representative marker-gene
sequences and an abundance table. It does not measure gene content. Use the
weighted NSTI values and the reference coverage of the study sequences when
deciding how much confidence to place in a prediction.

## Default SC run

The existing two-input invocation remains valid and selects SC by default:

```bash
microsuite functional_profile \
  --backend picrust2 \
  --table table.tsv \
  --rep-seqs rep-seqs.fasta \
  --output-dir functions
```

The explicit equivalent is:

```bash
microsuite functional_profile \
  --backend picrust2 \
  --table table.tsv \
  --rep-seqs rep-seqs.fasta \
  --output-dir functions \
  --picrust2-database SC
```

The table may be BIOM, TSV, or mothur shared format according to the upstream
PICRUSt2 contract. FASTA headers must be unique and must match the feature IDs
in the table exactly. SC places study sequences in bacterial and archaeal
references and selects the lower-NSTI domain for each sequence.

## Database selectors

| Selector | Behavior |
| --- | --- |
| `SC` | Default v2.6.3 PICRUSt2-SC dual-domain references. |
| `oldIMG` | Legacy PICRUSt2-oldIMG single-reference pipeline for comparability with older analyses. |
| `custom` | User-supplied single- or dual-domain reference layout and associated trait/marker files. |

For legacy reproducibility:

```bash
microsuite functional_profile \
  --backend picrust2 \
  --table table.tsv \
  --rep-seqs rep-seqs.fasta \
  --output-dir functions-oldimg \
  --picrust2-database oldIMG
```

The oldIMG selector uses the v2.6.3 `picrust2_pipeline_singleRef.py` entry
point. It is not the same reference set as SC, so oldIMG and SC results should
not be compared as if they were generated by one model.

The mapping overrides `--picrust2-pathway-map`, `--picrust2-reaction-func`, and
`--picrust2-regroup-map` are valid with SC, oldIMG, and custom databases. A
path-valued override is staged by Nextflow; `--picrust2-reaction-func` may also
be a symbolic upstream value such as `EC`.

## Custom references and traits

Custom inputs are individual options, not a free-form shell argument string.
A custom single-reference run has one placement reference and one set of
domain-specific tables:

```bash
microsuite functional_profile \
  --backend picrust2 \
  --table table.tsv \
  --rep-seqs rep-seqs.fasta \
  --output-dir functions-custom \
  --picrust2-database custom \
  --picrust2-ref-dir1 refs/custom \
  --picrust2-custom-trait-tables-ref1 refs/custom/ec.tsv.gz \
  --picrust2-marker-gene-table-ref1 refs/custom/16S.tsv.gz \
  --picrust2-no-pathways
```

A custom dual-reference run supplies both domains. Trait-table options are
repeatable:

```bash
microsuite functional_profile \
  --backend picrust2 \
  --table table.tsv \
  --rep-seqs rep-seqs.fasta \
  --output-dir functions-custom-dual \
  --picrust2-database custom \
  --picrust2-ref-dir1 refs/bacteria \
  --picrust2-ref-dir2 refs/archaea \
  --picrust2-custom-trait-tables-ref1 refs/bacteria/ec.tsv.gz \
  --picrust2-custom-trait-tables-ref1 refs/bacteria/ko.tsv.gz \
  --picrust2-custom-trait-tables-ref2 refs/archaea/ec.tsv.gz \
  --picrust2-custom-trait-tables-ref2 refs/archaea/ko.tsv.gz \
  --picrust2-marker-gene-table-ref1 refs/bacteria/16S.tsv.gz \
  --picrust2-marker-gene-table-ref2 refs/archaea/16S.tsv.gz \
  --picrust2-pathway-map refs/pathways.tsv \
  --picrust2-reaction-func EC \
  --picrust2-regroup-map refs/ec-to-reaction.tsv
```

The custom database contract follows upstream PICRUSt2:

- each reference directory contains the placement files required by the
  selected placement tool (reference FASTA/MSA, tree, HMM, and model files);
- each trait table has reference-genome IDs as rows and trait IDs as columns;
  genome IDs must agree with the corresponding reference set;
- each marker table has the same reference-genome IDs and a marker copy-number
  value for each genome;
- a pathway map describes the reaction/function-to-pathway relationship;
- `--picrust2-reaction-func` selects the trait family or custom table used as
  pathway reactions; and
- `--picrust2-regroup-map` maps selected trait IDs into the reaction IDs
  consumed by the pathway map.

If the custom trait family has no valid pathway mapping, pass
`--picrust2-no-pathways`. A custom map is required for meaningful pathways;
the SC MetaCyc map must not be silently reused for an unrelated trait ontology.
The v2.6.3 upstream instructions recommend adding a custom trait table to an
existing reference set when only a particular function is needed instead of
building a whole new database.

| Option | Meaning |
| --- | --- |
| `--picrust2-max-nsti VALUE` | Exclude sequences above this NSTI threshold before metagenome prediction. |
| `--picrust2-no-pathways` | Skip pathway inference. |
| `--picrust2-coverage` | Request pathway coverage. This is opt-in and experimental upstream; it is not produced by default. |
| `--picrust2-no-regroup` | Skip regrouping before pathway inference. |

## Outputs

`picrust2_manifest.json` is the microsuite stability boundary. It records the
selected database, effective PICRUSt2 options, software/runtime information,
and reference/custom-input choices needed to interpret the run.

Raw upstream files retain their PICRUSt2 names and layout:

```text
EC_metagenome_out/pred_metagenome_unstrat.tsv.gz
EC_metagenome_out/weighted_nsti.tsv.gz
KO_metagenome_out/pred_metagenome_unstrat.tsv.gz
pathways_out/path_abun_unstrat.tsv.gz
```

When `--picrust2-coverage` is explicitly passed, the pipeline additionally
produces `pathways_out/path_cov_unstrat.tsv.gz`. Coverage is an experimental
alternative pathway-presence signal. Its absence from a normal run is expected
and must not be interpreted as a failed run. Stratified and intermediate files
are raw upstream artifacts and can be larger and more version-sensitive than
the stable manifest contract.

Weighted NSTI is a sample-level, abundance-weighted nearest-sequenced taxon
index. Lower values indicate that the sample's sequences are, on average,
closer to sequences represented in the selected reference database. It is a
diagnostic of reference proximity, not an accuracy guarantee, and it does not
capture strain-level gene-content variation or horizontal gene transfer.

## Docker and Nextflow

Use the dedicated image when PICRUSt2 is not installed locally:

```bash
microsuite functional_profile \
  --backend picrust2 \
  --table table.tsv \
  --rep-seqs rep-seqs.fasta \
  --output-dir functions \
  --runtime docker \
  --image ghcr.io/qwerty239qwe/microsuite/microsuite-picrust2:sha-<commit>
```

Pin an immutable image tag for reproducibility. The image entrypoint is
`microsuite`; direct upstream diagnostics therefore require an explicit
entrypoint override:

```bash
docker run --rm --entrypoint picrust2_pipeline.py \
  ghcr.io/qwerty239qwe/microsuite/microsuite-picrust2:sha-<commit> --version
```

Nextflow's `-profile docker` selects the same image through
`microsuite_picrust2`. The module defaults to SC and retains the historical
two-input process call for SC and oldIMG. The custom branch declares one
Nextflow `path` collection containing every reference directory, trait table,
marker table, and map; the process rewrites each option to the staged task-local
path before invoking the CLI. Assets are staged into indexed subdirectories so
same-named files from bacterial and archaeal references cannot collide.

The spelling is intentionally different at the two interfaces:

- CLI flags are hyphenated, for example
  `--picrust2-database oldIMG`, `--picrust2-ref-dir1 refs/custom`, and
  `--picrust2-custom-trait-tables-ref1 refs/custom/ec.tsv.gz`.
- Nextflow parameters are underscored, for example
  `--picrust2_database oldIMG`, `--picrust2_ref_dir1 refs/custom`, and
  `--picrust2_custom_trait_tables_ref1 refs/custom/ec.tsv.gz`.

Repeatable trait tables may be supplied as a list or comma-separated value.
The module quotes each generated argument and does not accept raw shell
arguments. `--picrust2_no_regroup` is the Nextflow spelling of the forwarded
`--picrust2-no-regroup` CLI switch.

## Scientific limitations and migration

PICRUSt2 is reference-dependent functional-potential inference from marker
genes. Predictions are constrained by the genomes and annotations in the
selected reference set. Accuracy can vary by environment and taxonomic
representation; 16S data generally cannot resolve strain-level gene content.
Compare against shotgun metagenomes when a conclusion depends on a specific
function or differential abundance claim.

Before PICRUSt2 v2.6.0, the default database was oldIMG. In 0.6.0, existing
microsuite calls keep their two required inputs but now default to SC. Add
`--picrust2-database oldIMG` when reproducing a pre-v2.6 PICRUSt2 analysis.
Expect changes in placement, NSTI, functional abundance, pathway abundance,
and available annotations when migrating to SC. Coverage remains off unless
`--picrust2-coverage` is requested.
